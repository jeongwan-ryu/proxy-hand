# ProxyHand 상태와 흐름

* 작성일: 2026-11-20
* 목적: 작업차 모드 · 파이 상태 · 작업대 상태가 **무슨 일이 생기면 어떻게 바뀌는지**를 한곳에서 `→`로 짧게 봅니다. 일반 흐름과 예외 상황을 모두 담습니다.
* **기준 문서가 아닙니다.** 시스템 설계(04)의 5.2, 6~9, 11~13장을 모아 정리한 것입니다. 이 문서와 04가 다르면 **04를 따릅니다.** 규칙을 바꿀 때는 04를 고치고, 같은 커밋에서 이 문서도 고칩니다.
* 줄 끝의 `(6.3)`처럼 적은 번호는 04의 장 번호, `(05-4.4)`는 인터페이스 정의의 장 번호입니다.
* 읽는 법: `→`는 "그다음". `[버튼]`은 조종 화면 버튼. `작업대: 담는 중`처럼 콜론 뒤는 그 순간 바뀐 상태.

## 1. 상태 세 가지

| 상태 | 누가 관리 | 값 |
| --- | --- | --- |
| 작업차 모드 | 관제 (노트북) | 대기 `idle` · 조종 `manual` · 가르치기 `teach` · 혼자 하기 `auto` · 정지 `stopped` |
| 파이 상태 | 파이 (작업차마다) | `idle` · `driving` · `arrived` · `stopped` · `error` |
| 작업대 상태 | 관제 | 비어 있음 `empty` · 담는 중 `filling` · 담기 끝 `filled` |

작업차 모드와 파이 상태는 이름이 비슷하지만 **따로** 움직입니다. 예: 모드는 "조종"인데 파이는 `driving`(정거장으로 가는 중)일 수 있습니다.

### 1.1 작업차 모드 (6.1)

- 대기 → [조종] → 조종
- 대기 → [가르치기] → 가르치기 (기록 시작)
- 대기 → 작업 고르고 [시작] → 혼자 하기 (파이가 대기 정거장에서 `arrived`일 때만)
- 조종 → [가르치기] → 가르치기
- 조종 → [대기] → 대기
- 가르치기 → [기록 끝] + 이름 → 조종 (작업 파일 저장)
- 혼자 하기 → 작업 끝, 반복 꺼짐 → 대기
- 혼자 하기 → 작업 끝, 반복 켜짐 → 혼자 하기 (처음 단계부터)
- 혼자 하기 → 보관함 빔 (작업차 1) / 작업차 1 끝 + 작업대 빔 (작업차 2) → 대기
- 모든 모드 → [정지] · 스페이스바 · "정지" 오류 → 정지
- 정지 → [조종] → 조종 (**정지에서 갈 수 있는 모드는 조종뿐**)

### 1.2 파이 상태 (05-4.4)

- 켜짐 → `idle` (어느 정거장인지 모름)
- `idle`·`arrived`·`stopped`·`error` → `set_station` 받음 → `arrived`
- `arrived`·`stopped` → `goto` 받음 (다른 정거장) → `driving` → 목표 정지선 → `arrived`
- `arrived` → `goto` 받음 (지금 정거장) → 움직이지 않고 `arrived`를 다시 보냄
- 모든 상태 → `stop` 받음 → `stopped`
- 모든 상태 → 생존 신호 1초 넘게 안 옴 → `stopped` (`link_lost`)
- `stopped` → `resume` 받음 → 멈추기 직전 `arrived`였고 그 뒤 안 움직였으면 `arrived`, 아니면 `stopped` 그대로
- `driving` → 선 놓침 → `error` (`line_lost`)
- `driving` → 정지선 사이 시간이 너무 김 → `error` (`line_missed`)
- 모든 상태 → micro:bit 응답 없음 3번 → `error` (`serial_fail`)
- 손 명령(`hand`)은 **`arrived`일 때만** 받음. 나머지 상태에서는 조용히 버림

### 1.3 작업대 상태 (6.3)

맵 위 웹캠이 보는 두 가지로만 정합니다: **작업대에 바이알이 있나**(마커가 가려졌나), **콕 LED가 켜졌나**(콕이 열렸나).

- 비어 있음 → 바이알 있음 + LED 꺼짐 → 담는 중
- 담는 중 → LED 켜짐 → 담기 끝
- 담는 중 → 바이알 없어짐 → 비어 있음
- 담기 끝 → LED 꺼짐 → 담기 끝 **유지** (한 번 켜졌으면 기억)
- 담기 끝 → 바이알 없어짐 → 비어 있음
- 바이알 판단이 "보류"인 동안은 상태를 바꾸지 않음 (예외는 3장 B)

### 1.4 보류 (5.2)

작업차의 AiHand가 마커를 가렸을 수 있을 때는 맵 비전 결과를 믿지 않고 "보류"(`unknown`)로 둡니다.

- 작업차 1이 `driving` → 보관함 칸 1~3 + 작업대 모두 보류
- 작업차 1이 `storage_k`에 서 있음 → 칸 k만 보류
- 작업차 1이 `bench_1`에 서 있음 → 작업대 보류
- 작업차 2가 `driving` 또는 `bench_2`에 서 있음 → 작업대 보류 (보관함은 그대로)
- 작업차가 정거장 사이에서 멈춤 → 그 작업차가 닿는 마커 모두 보류
- 연결이 끊긴 작업차 → 보류 원인으로 보지 않음
- 보류가 풀림 → 맵 비전 값이 **0.5초 동안 같아야** 그 값을 씀

## 2. 일반 흐름

### 2.1 시작 준비 (13)

맵 준비 (보관함 바이알 3개, 콕 닫힘, 작업대 빔) → 작업차 전원 → 파이: `idle` → 작업차를 손으로 대기 정거장에 올림 → 노트북 `start_laptop.bat` → 화면에 연결 ● 확인 → 관제가 첫 맵 비전 값을 받음 → 작업대: 비어 있음 → 작업차마다 [위치 지정: 대기 정거장] → 파이: `idle` → `arrived` → 관제가 처음 자세를 보냄 (손가락 펴고 손목 `drive_wrist`, **파이가 `idle`이었을 때만**, 9.5) → 손 맞춤 [손 펴기 기록] → [주먹 기록] → 손 인식: 맞춤 완료 → [조종] → 손을 쥐었다 폄 → [대기]

### 2.2 조종 (6.1, 9.3)

[조종 대상 선택] → [조종] → 모드: 조종 → 조종자가 손을 움직임 → 손 인식이 손가락 굽힘 r(0~1)·손목 각도를 보냄 → 관제가 그 작업차 AiHand 보정값으로 서보 각도로 바꿈 (편·쥔 각도에서 5° 안쪽으로 자름) → 파이 → micro:bit → AiHand가 따라 함

- 관제가 손 각도를 보내는 조건: 조종 대상 + 조종·가르치기 모드 + 연결됨 + 파이 `arrived` + AiHand 보정 파일 있음 + 조종자 손 맞춤 끝 + **손을 펴서 시작함** (9.6)
- 시작 (9.6): 잠김 → 손가락 5개를 쫙 펴서 0.3초 유지 → 시작 (편 손은 안 보냄) → 손가락마다 조종자가 AiHand만큼 쥐면 붙음 → 붙은 손가락·손목만 따라 함 → 다 붙으면 모두 따라 함
- 놓기 경고 (9.7): AiHand가 쥐고 있음(평균 ≥ 0.6) + 놓는 곳 아님(대기 1·2, 콕) + 손을 폄 → 손가락 멈춤(손목은 따라 감) + 손 상태 줄 경고 → 다시 쥐면 경고 꺼짐 / [놓기 허용]·Enter → 이번 한 번 폄 → 다시 쥐면 허용 풀림
- AiHand 모양을 모름 (관제를 다시 켬): 쥐고 있다고 봄 → 주먹을 쥐어 5개 모두 붙기 전에는 아무것도 안 보냄
- 다시 잠김: 조종 대상의 모드가 바뀜 / 조종 대상이 바뀜 / 조종 대상이 도착함 / 손이 0.5초 넘게 안 보였다 다시 보임 / 손 인식 서비스 꺼짐 / 손 맞춤 다시 함
- 모든 서보 변화가 2° 미만이면 보내지 않음

### 2.3 정거장 이동 (8, 9.5, 05-4.3)

[정거장 버튼] → 관제가 주행 자세를 보냄 (**손목만** `drive_wrist`로, 손가락은 그대로) → 0.3초 기다림 (이동 중 손 명령 안 보냄) → `goto` → 파이: `driving` → 작업차 1이면 보관함·작업대 보류 → 정지선 셈 → 목표 정지선 → 파이: `arrived` → 보류 풀림 (0.5초 뒤 값 사용) → 손 따라 하기 잠김 → 손을 펴서 시작하면 손 조종 다시 됨 (9.6)

### 2.4 가르치기 → 저장 (8)

[가르치기] → 모드: 가르치기, 기록 시작 → 손 동작 (보낸 손 각도가 시간 간격과 함께 쌓임) → [정거장] (`goto` 단계로 쌓임, 보관함 칸은 `storage_*`로) → 도착 → 손 동작 (새 손 단계) → … → [기록 끝] + 이름 → `data/tasks/<시각>_<이름>.json` 저장 → 모드: 조종

- 주행 자세는 기록하지 않음 (재생할 때 관제가 다시 붙임)
- 손 인식이 끊긴 동안은 기록이 없음 → 재생 때 그 시간만큼 마지막 자세 유지

### 2.5 혼자 하기: 작업차 1 한 번 (7.1, 7.2)

`wait_1`에서 [시작] → 모드: 혼자 하기 → 작업대가 비어 있을 때까지 기다림 (0.2초마다 확인) → 보관함 칸 중 바이알이 있는 가장 작은 번호 고름 (예: 2번) → `storage_2`로 이동 → 칸 2 보류 → 집기 동작 재생 → `bench_1`로 이동 → 작업대 보류 → 놓기 동작 재생 → `cock`으로 이동 → 보류 풀림 → 0.5초 → 작업대: 담는 중 → 콕을 돌림 (LED 켜짐) → 작업대: 담기 끝 → 1초 유지 → 다시 돌림 (LED 꺼짐) → 작업대: 담기 끝 유지 → `wait_1`로 이동 → 한 번 끝 → [성공]/[실패] 누를 수 있음

- 재생: 프레임을 기록된 시간 간격대로 보냄 → 각 손 단계의 마지막 프레임은 0.1초 간격으로 3번 (UDP라 하나가 빠져도 마지막 자세가 도착하게)
- 작업의 마지막 이동이 `wait_1`이 아니면 관제가 `wait_1` 이동을 자동으로 붙임 (파일은 그대로)
- `cock`에 도착하자마자 콕을 열어 0.5초 안에 LED가 켜지면 → "보류 중 LED가 켜짐"(3장 B9)으로 처리 → 바로 담기 끝

### 2.6 혼자 하기: 작업차 2 한 번 (7.2)

`wait_2`에서 [시작] → 모드: 혼자 하기 → 작업대가 담기 끝일 때까지 기다림 → `bench_2`로 이동 → 작업대 보류 → 집기 동작 재생 → `meter`로 이동 → 보류 풀림 → 0.5초 → 바이알 없음 → 작업대: 비어 있음 → 투입구에 넣기 + 버튼 누르기 재생 → `wait_2`로 이동 → 한 번 끝

### 2.7 두 대가 같이 (7.2)

```
작업차 1: 집기 → bench_1에 놓기 → cock 열고 닫기 ───────────────→ wait_1 → (작업대 빌 때까지 기다림) → 다음 바이알
작업대  :            담는 중 ──→ 담기 끝 ──────────────────────────→ 비어 있음
작업차 2:   (담기 끝 기다림) ──────→ bench_2에서 집기 → meter ──────────────→ wait_2 → (담기 끝 기다림)
```

- 작업차 2는 담기 끝이 되면 바로 출발 (작업차 1이 콕을 닫는 중이어도 됨, 두 길이 겹치지 않음)
- 작업차 1의 다음 반복은 작업차 2가 바이알을 가져가 작업대가 빈 뒤에 시작

### 2.8 반복과 끝 (5.2, 7.2)

- 반복 켜짐 → 한 번 끝 → 대기 정거장에서 출발 조건 다시 확인 → 다음 반복
- 작업차 1: 반복 중 보관함 칸이 모두 빔 → 모드: 대기, 알림 "보관함 비었음" (정상 종료)
- 작업차 2: 작업차 1의 반복이 끝남 + 작업대 빔 → 모드: 대기, 알림 "보관함 비었음" (정상 종료)
- 반복 꺼짐 → 한 번 끝 → 모드: 대기, 알림 "작업 끝"
- 반복 한 번이 끝날 때마다 [성공]/[실패] → 반복 번호와 함께 로그

## 3. 예외 상황

한 줄 형식: **상황 → 관제·파이가 하는 일 → 모드·파이·작업대 → 화면** / **복구**.
"정지"로 가는 오류는 **그 작업차만** 정지합니다. 다른 작업차는 하던 일을 계속합니다. 스페이스바만 둘 다 정지합니다 (11).

### A. 작업차 · 파이 (11)

**A1. 선 놓침 `line_lost`**
`driving` 중 선을 놓침 → 파이가 바퀴를 멈춤, 손 유지 → 파이: `error` → 관제: 모드 정지 (`stop`은 보내지 않음, 이미 멈춤) → 화면 "작업차 n 선 놓침"
복구: 작업차를 손으로 가까운 정거장에 올림 → [위치 지정] → 파이: `arrived` → 손은 그대로 (처음 자세를 보내지 않음, 바이알을 쥐고 있을 수 있음, 9.5) → [조종] (`resume`은 보내지 않음, 이미 `arrived`)

**A2. 정지선 놓침 `line_missed`**
정지선 사이 시간이 기준(보통 1.5배, 느린 구간 3배)보다 김 → 이후 A1과 같음 → 화면 "작업차 n 정지선 놓침"
복구: A1과 같음

**A3. AiHand 연결 오류 `serial_fail`**
micro:bit가 0.2초 안에 답하지 않음이 3번 → 파이가 바퀴를 멈춤 → 파이: `error` → 관제: 모드 정지 → 화면 "작업차 n AiHand 연결 오류"
복구: USB·배터리 확인 → 파이가 1초마다 다시 연결 → [위치 지정] (손은 그대로, A1과 같음) → [조종] (파이는 `error`에서 `resume`을 받지 않음)

**A4. 연결 끊김 `car_link_lost`**
관제와 파이의 TCP 연결이 끊김, 또는 파이 보고가 1.5초(`status_period_s` × 3) 동안 하나도 안 옴 (와이파이가 조용히 끊기면 끊겼다는 신호가 오지 않으므로) → 파이: 생존 신호가 1초 넘게 안 와서 스스로 멈춤, `stopped` → 관제: **모드가 무엇이든** 정지 (대기여도) → 화면 "작업차 n 연결 끊김" → 관제가 1초마다 다시 접속 → 접속되면 `time_sync` → 파이가 `link_lost` 기록을 보냄 (로그만, 화면 없음)
복구: 화면에 연결 ● → [조종] → 관제가 `resume`을 보냄 → 파이: `arrived` → 손 조종 됨
왜 대기여도 정지인가: 대기로 두면 [조종]이 `resume`을 보내지 않아 파이가 `stopped`에 남고, 손 조종과 [시작]이 모두 막힘

**A5. 이동 시간 초과 `goto_timeout`**
`goto` 후 30초 안에 `arrived`가 안 옴 → 관제가 `stop`을 보냄 → 모드 정지 → 화면 "작업차 n 이동 시간 초과"
복구: [조종]

**A6. 할 수 없는 명령 `cmd_rejected`**
관제가 막음 (지금 모드에서 안 되는 버튼, 다른 고리의 정거장) 또는 파이가 `reject`를 보냄 → 아무것도 바뀌지 않음 → 화면 "할 수 없는 명령: …"
단, 혼자 하기 중에 파이가 `goto`를 거절 → 그 작업차 정지 (작업을 이어 갈 수 없음)

### B. 작업대 (6.3)

**B7. 바이알을 놓았는데 콕이 이미 열림 `cock_open`**
작업대: 비어 있음 + 바이알 있음 + LED 켜짐 → 작업대: 비어 있음 유지 → 관제가 작업차 1에 `stop` → 작업차 1 모드 정지 → 화면 "콕이 열려 있음" (같은 상황이 이어져도 한 번만)
복구: B8

**B8. `cock_open` 경고 뒤 콕을 닫음**
[조종] → 콕 닫음 → LED 꺼짐 → 바이알은 그대로 → 작업대: 담는 중 (방금 놓은 것과 같게 봄) → 콕을 다시 열면 → 작업대: 담기 끝

**B9. 보류 중에 LED가 켜짐**
작업대: 비어 있음 → 작업차가 움직여 작업대 보류 시작 → 관제가 기억: ① 보류 시작 때 LED가 켜져 있었나 ② 보류 중에 LED가 켜진 적 있나 → 보류 풀림 + 바이알 있음 →
- ① 아니요, ② 예 → 작업대: 담기 끝 (바로)
- ① 예 → `cock_open` (B7과 같음)
- ① 아니요, ② 아니요 → 작업대: 담는 중

**B10. 관제를 켰을 때 작업대에 바이알이 남아 있음 `bench_not_empty`**
첫 맵 비전 값: 작업대 바이알 있음 → 작업대: 비어 있음 + 경고 "작업대에 바이알이 남아 있음" → 작업차 1은 혼자 하기를 시작하지 않음 (기다림) → 남은 바이알로 담는 중이 되지 않음
복구: 바이알을 치움 → 경고 사라짐 → 이후 정상

**B11. 맵 위 웹캠이 콕 LED를 알아보지 못함**
LED 값이 `null` → 담기 끝이 되지 않음 → 작업차 2가 출발하지 않음
복구: 아직 정하지 않음 (열린 문제 1)

### C. 보관함 (5.2)

**C12. 시작할 때 바이알이 없음 `vial_not_found`**
[시작] → 첫 반복에서 칸 1~3 모두 없음 → 움직이지 않음 → 모드: 대기 → 화면 "바이알을 찾지 못함"
복구: 바이알을 놓고 다시 [시작]

**C13. 반복 중 보관함이 빔 `storage_empty`**
2.8과 같음 (정상 종료)

**C14. 칸이 보류라 고를 수 없음**
칸 하나라도 보류 → 고르지 않고 0.2초 뒤 다시 봄 (작업차 1은 `wait_1`에서 고르므로 보통 보류 없음)

### D. 손 인식 · 서비스 (11)

**D15. 손 인식 끊김 `hand_lost`**
손이 AiHand를 움직이던 중(따라 하는 중·이어 붙이는 중·놓기 막음)에 손이 안 보임 (그 밖에 안 보이면 알림 없이 맨 위 줄 "인식 끊김"과 로그만) → 손 각도 안 보냄 → AiHand는 마지막 자세 유지 → 모드 그대로 → 화면 "손 인식 끊김", 손 영상 테두리 빨강
복구: 0.5초 안에 다시 보이면 자동으로 이어짐. 더 길면 잠김 → 손을 펴서 다시 시작 (AiHand가 쥐고 있으면 주먹을 쥐어야 손가락이 붙음, 9.6)

**D16. 손 인식 서비스 꺼짐 `hand_service_down`**
1초 넘게 손 메시지가 안 옴 → 손 각도 안 보냄 → 모드 그대로 → 화면 "손 인식 서비스 꺼짐", [손 펴기 기록]/[주먹 기록] 흐림
복구: 손 인식 서비스 다시 실행

**D17. 맵 비전 서비스 꺼짐 `vision_service_down`**
1초 넘게 맵 비전 메시지가 안 옴 → 칸·작업대 값 모두 모름 → **혼자 하기 중인 작업차만** `stop` + 모드 정지, 나머지 그대로 → 화면 "맵 비전 서비스 꺼짐" → 꺼져 있는 동안 [시작] 거절
복구: 맵 비전 다시 실행 → [조종]

### E. 조종자 입력 (6.1, 12)

**E18. [정지] / 스페이스바**
[정지] → 그 작업차에 `stop` → 모드 정지 (하던 혼자 하기·가르치기 기록·보내려던 이동은 버림) / 스페이스바 → 두 작업차 모두. 입력 칸에 글자를 쓰는 중에도 먼저 처리

**E19. 정지 → [조종]: `resume`을 보내나**
- 파이가 `stopped` → `resume` 보냄 → 멈추기 전 `arrived`였으면 `arrived`로, 정거장 사이였으면 `stopped`에 남아 `goto`만 받음
- 파이가 이미 `arrived` ([위치 지정]을 한 뒤) → 보내지 않음 (파이가 거절하므로)

**E20. 가르치기 중 정지**
가르치기 → [정지] 또는 오류 → 모드 정지 → 쌓던 기록 버림 (로그에 `record_discard`)

**E21. 단계 없이 [기록 끝]**
→ 거절, 가르치기 모드 그대로

**E22. [시작]이 막히는 경우**
대기 정거장이 아님 / 파이가 `arrived`가 아님 / 다른 작업차에서 저장한 작업 / 맵 비전 꺼짐 / AiHand 보정 파일 없음 / 작업에 이 작업차 고리에 없는 정거장 → 거절, 모드 대기 그대로

**E23. 실행 중인 작업 [삭제]**
→ 거절

**E24. AiHand 보정 파일이 없는 작업차**
관제는 뜨지만 그 작업차에는 손 각도를 보내지 않고 [시작]도 거절 (05-9.9)
