# ProxyHand 인터페이스 정의

* 작성일: 2026-11-18
* 함께 보는 문서: ProxyHand 시스템 설계 (서비스 구성, 동작 규칙, 오류 처리)
* 목적: **두 사람의 코드가 똑같이 맞춰야 하는 약속**을 한곳에 모읍니다. 서비스 사이 메시지, 오류·알림 코드, 설정·데이터 파일 형식이 들어 있습니다. 이 문서와 코드가 다르면 이 문서를 기준으로 고치고, 이 문서를 바꿀 때는 두 사람이 같이 확인한 뒤 10장에 남깁니다.
* 코드: 메시지 이름과 필드는 `shared/messages.py`에, 설정 읽기는 `shared/config.py`에 이 문서 그대로 옮깁니다.

## 1. 한눈에 보기

```
            ┌──────────────── 노트북 ────────────────┐
 브라우저 ◀─ws:8000─▶ 관제 서비스 ◀─udp:5100── 손 인식 서비스 ─http:8091─▶ 브라우저
   ▲                  │   ▲      ──udp:5102─▶ (손 맞춤 요청)
   │                  │   └─────udp:5101── 맵 비전 서비스 ─http:8090─▶ 브라우저
   │                  │

   │                  ▼

```

## 3. 공통 규칙

| 규칙 | 내용 |
| --- | --- |
| 메시지 하나 | **JSON 객체 한 줄** (UTF-8). TCP와 WebSocket은 줄바꿈 `\n`으로 메시지를 나눔. UDP는 패킷 하나에 메시지 하나 |
| 공통 필드 | 모든 메시지에 `topic`, `seq`, `t`가 있음 (아래 표) |
| 모르는 필드 | 받는 쪽은 모르는 필드를 무시함 (한쪽에 필드를 먼저 추가해도 안 깨지게) |
| 모르는 `topic` | 무시하고 로그에 한 줄 남김 |
| 필드가 빠졌거나 타입이 틀림 | 그 메시지를 버리고 로그에 남김. TCP 명령이면 `reject`로 알림 (4.2) |
| 정거장 ID | `shared/config/map.yaml`에 있는 값만 씀 (`wait_1`, `storage_1` …) |
| 단위 | 각도 = 도(°, 정수), 손 이동 시간 = 밀리초(`ms`, 정수), 거리 = mm(실수), 그 밖의 시간 = 초(실수) |
| 작업차 번호 | `{n}` = 1 또는 2. JSON 안의 키로 쓸 때는 문자열 `"1"`, `"2"` |
| 이름 규칙 | 필드 이름은 영어 소문자 + `_` (예: `moving_to`) |

| 공통 필드 | 타입 | 뜻 | 예 |
| --- | --- | --- | --- |
| `topic` | 문자열 | 메시지 이름 | `"car1/hand"` |
| `seq` | 정수 | 보내는 쪽이 `topic`마다 0부터 1씩 올려 매기는 순번 | `1532` |
| `t` | 실수 | 보낸 시각. 보내는 기계 기준 유닉스 시간(초) | `1763358812.214` |

**UDP 순번 규칙:** 받는 쪽은 같은 `topic`에서 마지막으로 받은 `seq`보다 작거나 같은 메시지를 버립니다(늦게 도착한 옛 값). 단, 받은 `seq`가 마지막 값보다 1000 넘게 작으면 보내는 쪽이 다시 켜진 것으로 보고 받아들입니다.

## 4. 노트북 ↔ 파이 (관제 서비스 ↔ 작업차 서비스)

### 4.1 관제 → 파이

| topic | 방식 | 언제 | 필드 | 파이가 하는 일 |
| --- | --- | --- | --- | --- |
| `car{n}/hand` | UDP | 손 명령 조건이 될 때 1초 15~30번, 재생 중 | `angles`: 정수 6개 [서보1, …, 서보6] (0~180), `ms`: 정수 (0~1000) | `arrived`일 때만 micro:bit에 `M`으로 전달 (최신 값만, 시스템 설계 9.4) |
| `car{n}/goto` | TCP | 정거장 이동 지시 | `station`: 정거장 ID | 정지선을 세며 이동 → 목표 정지선에서 멈추고 `arrived` |
| `car{n}/set_station` | TCP | [위치 지정] (작업차를 손으로 정거장에 올린 뒤) | `station`: 정거장 ID | 지금 위치를 그 정거장으로 두고 `arrived` |
| `car{n}/stop` | TCP | [정지], 스페이스바, 오류 | `reason`: 문자열 (로그용, 없어도 됨) | 바퀴 즉시 멈춤, 손 유지 → `stopped` |
| `car{n}/resume` | TCP | 정지 모드에서 [조종] | 없음 | 6.2(시스템 설계)의 규칙대로 `arrived` 또는 `stopped` 유지 |
| `car{n}/heartbeat` | TCP | 0.2초마다 | 없음 | 마지막 수신 시각 갱신. 1초 넘게 안 오면 `stopped` + `link_lost` |
| `car{n}/time_sync` | TCP | 관제가 파이에 접속한 직후 1번 | `now`: 노트북의 지금 시각(유닉스 시간, 초) | `now − 파이 시각`을 기억해 두고, 이후 보내는 메시지의 `t`와 로그 시각에 더함 (파이 시스템 시계는 안 바꿈) |

예시:
```json
{"topic":"car1/hand","seq":1532,"t":1763358812.214,"angles":[20,120,118,121,130,90],"ms":33}
{"topic":"car1/goto","seq":12,"t":1763358812.500,"station":"storage_2"}
{"topic":"car1/stop","seq":13,"t":1763358820.000,"reason":"space"}
```

### 4.2 파이 → 관제

| topic | 방식 | 언제 | 필드 |
| --- | --- | --- | --- |
| `car{n}/status` | TCP | 0.5초마다 + 상태가 바뀔 때 + 관제가 접속한 직후 | `state`: 파이 상태 (4.4), `station`: 마지막으로 도착한 정거장 ID 또는 `null`, `moving_to`: 가는 중인 정거장 ID 또는 `null`, `serial_ok`: micro:bit 연결 여부 (불) |
| `car{n}/arrived` | TCP | 목표 정지선에서 멈췄을 때, 또는 `set_station`을 받았을 때 | `station`: 정거장 ID |
| `car{n}/error` | TCP | 문제가 생겼을 때 (`link_lost`는 연결이 돌아온 뒤 보냄) | `code`: 8장의 파이 코드, `text`: 설명 |
| `car{n}/reject` | TCP | 지금 상태에서 받을 수 없는 명령을 받았을 때 (`hand`는 제외, 조용히 버림) | `cmd`: 받은 topic, `state`: 지금 상태, `text`: 이유 |

예시:
```json
{"topic":"car1/status","seq":301,"t":1763358813.0,"state":"driving","station":"wait_1","moving_to":"storage_2","serial_ok":true}
{"topic":"car1/arrived","seq":302,"t":1763358814.7,"station":"storage_2"}
{"topic":"car1/error","seq":310,"t":1763358830.1,"code":"line_lost","text":"선을 0.5초 동안 찾지 못함"}
```

### 4.3 주고받는 순서 예 (정거장 이동)

```
관제                                         파이
 │── goto {storage_2} ──────────────────────▶│ driving
 │◀─────────────────────── status {driving} ─│   정지선 세기 + 구간 시간 확인
 │◀──────────────────────── arrived {storage_2}│ arrived (목표 정지선에서 멈춤)
 │── hand {angles…} (UDP, 여러 번) ─────────▶│ → micro:bit
```

정지선을 놓친 경우:
```
 │── goto {bench_1} ────────────────────────▶│ driving
 │◀──────────── error {line_missed} ─────────│ error (구간 시간 초과로 멈춤)
```

### 4.4 파이 상태 변화와 받는 명령

**상태 변화**

| 지금 | 받은 것 / 일어난 일 | 다음 |
| --- | --- | --- |
| (켜짐) | — | `idle` |
| `idle`, `arrived`, `stopped`, `error` | `set_station` | `arrived` |
| `arrived`, `stopped` | `goto` (지금 정거장과 다른 곳) | `driving` |
| `driving` | 목표 정지선 시작을 봄 | `arrived` |
| `stopped` | `resume` (멈추기 직전 `arrived`였고 그 뒤 안 움직임) | `arrived` |
| `stopped` | `resume` (그 밖) | `stopped` |
| 모든 상태 | `stop` | `stopped` |
| 모든 상태 | 생존 신호 1초 넘게 끊김 | `stopped` (`link_lost`) |
| `driving` | 선 놓침 | `error` (`line_lost`) |
| `driving` | 정지선 사이 시간이 기준보다 너무 김 | `error` (`line_missed`) |
| 모든 상태 | micro:bit 응답 없음 3번 | `error` (`serial_fail`) |

**상태별로 받는 명령** (O = 받음, X = `reject`로 거절, — = 조용히 버림)

| 명령 / 상태 | `idle` | `driving` | `arrived` | `stopped` | `error` |
| --- | --- | --- | --- | --- | --- |
| `hand` | — | — | O | — | — |
| `goto` | X | X | O | O | X |
| `set_station` | O | X | O | O | O |
| `stop` | O | O | O | O | O |
| `resume` | X | X | X | O | X |
| `heartbeat` | O | O | O | O | O |
| `time_sync` | O | O | O | O | O |

* `goto`로 지금 서 있는 정거장을 보내면 움직이지 않고 바로 `arrived`를 다시 보냅니다.
* `stopped`에서 `goto`를 받으면, 정거장 사이에서 멈췄어도 지나온 정지선 수를 기억하므로 이어서 셉니다.

## 5. 노트북 안 서비스끼리 (UDP 127.0.0.1)

### 5.1 `hand/pose` (손 인식 → 관제, 포트 5100)

손이 보이면 1초 30번(카메라 속도), 안 보이면 1초 10번 보냅니다.

| 필드 | 타입 | 뜻 |
| --- | --- | --- |
| `detected` | 불 | 손이 보이는지 |
| `fingers` | 실수 5개 또는 `null` | [엄지, 검지, 중지, 약지, 새끼] 굽힘 정도. 0 = 편 상태, 1 = 쥔 상태. 손이 안 보이면 `null` |
| `wrist` | 실수 또는 `null` | 손목 좌우 회전(°), −90~+90. 0 = 손바닥이 카메라를 봄, + = 조종자 기준 오른쪽으로 돌림 |
| `calibrated` | 불 | 조종자 손 맞춤(펴기·쥐기)을 마쳤는지. `false`면 관제는 손 명령을 보내지 않음 |
| `fps` | 실수 | 최근 1초 처리 속도 |

```json
{"topic":"hand/pose","seq":88123,"t":1763358812.190,"detected":true,"fingers":[0.12,0.85,0.90,0.88,0.80],"wrist":-12.5,"calibrated":true,"fps":29.6}
```

### 5.2 `hand/calib` (관제 → 손 인식, 포트 5102)

| 필드 | 타입 | 뜻 |
| --- | --- | --- |
| `step` | 문자열 | `"open"` = 지금 손을 편 값으로 저장, `"fist"` = 쥔 값으로 저장, `"reset"` = 맞춤 지우기 |

* 손 인식 서비스는 `open`과 `fist`를 둘 다 받은 뒤부터 `calibrated: true`를 보냅니다. 맞춤 값은 `data/calibration/operator.json`에 저장해 다시 켜도 유지합니다.

### 5.3 `vision/state` (맵 비전 → 관제, 포트 5101)

1초 10번 보냅니다. 맵 비전은 **마커가 가려졌는지만** 판단합니다. 작업차 때문에 가려졌을 수 있는지(보류)는 관제가 판단합니다(시스템 설계 5.2).

| 필드 | 타입 | 뜻 |
| --- | --- | --- |
| `slots` | 객체 `{"1":…, "2":…, "3":…}` | 보관함 칸별 `"occupied"`(마커가 0.5초 넘게 안 보임) / `"empty"`(0.5초 넘게 보임) / `"unknown"`(시작 직후 첫 판단 전 0.5초. 그 뒤로는 마커를 잠깐 못 읽어도 앞서 정한 값을 유지) |
| `bench` | 문자열 | 작업대 마커, 같은 값 |
| `cock_led` | 불 또는 `null` | 콕 LED 켜짐 여부. 판단할 수 없으면(보정 파일 없음 등) `null` |
| `fps` | 실수 | 최근 1초 처리 속도 |

```json
{"topic":"vision/state","seq":5012,"t":1763358815.10,"slots":{"1":"empty","2":"occupied","3":"occupied"},"bench":"empty","cock_led":false,"fps":29.8}
```

## 6. 조종 화면 ↔ 관제 (WebSocket `ws://localhost:8000/ws`)

* 브라우저가 접속하면 관제는 바로 `ui/state`를 한 번 보내고, 그 뒤 1초 5번 + 바뀔 때마다 보냅니다.
* 브라우저에는 화면 상태를 따로 저장하지 않고, 받은 `ui/state`를 그대로 그립니다(새로 고침해도 같은 화면).

### 6.1 관제 → 브라우저

**`ui/state`**

| 필드 | 타입 | 뜻 |
| --- | --- | --- |
| `selected_car` | 정수 | 조종 대상 작업차 |
| `cars` | 객체 `{"1":{…},"2":{…}}` | 작업차별 상태 (아래 표) |
| `bench` | 문자열 | 작업대 상태 `"empty"` / `"filling"` / `"filled"` |
| `bench_vial` | 문자열 | 작업대 바이알 `"occupied"` / `"empty"` / `"unknown"` (보류 적용) |
| `slots` | 객체 | 칸별 `"occupied"` / `"empty"` / `"unknown"`. `vision/state` 값에 관제가 보류 규칙을 적용한 값 |
| `cock_led` | 불 또는 `null` | |
| `hand` | 객체 | `{"service": 불, "detected": 불, "calibrated": 불, "fingers": 실수 5개 배열 또는 null}`. `fingers`는 조종자 손가락 쥔 정도(0 = 편, 1 = 쥔, 엄지부터), 손이 안 보이면 `null`. 화면의 이어 붙이기 막대용 |
| `vision` | 객체 | `{"service": 불}` |
| `map_video_url` | 문자열 | `"http://localhost:8090/video"` |
| `hand_video_url` | 문자열 | `"http://localhost:8091/video"` |
| `tasks` | 배열 | `[{"id": 파일 이름, "name": 이름, "car": 정수, "created": 시각 문자열}]` |

`cars` 안의 값:

| 필드 | 타입 | 뜻 |
| --- | --- | --- |
| `mode` | 문자열 | `"idle"`(대기) / `"manual"`(조종) / `"teach"`(가르치기) / `"auto"`(혼자 하기) / `"stopped"`(정지) |
| `link` | 불 | 파이와 TCP 연결 여부 |
| `pi_state` | 문자열 또는 `null` | 파이의 마지막 `state` |
| `station` | 문자열 또는 `null` | 마지막 정거장 |
| `moving_to` | 문자열 또는 `null` | 가는 정거장 |
| `task` | 문자열 또는 `null` | 실행 중인 작업 이름 |
| `step` | 문자열 또는 `null` | 진행 단계 표시 (예: `"3/6"`) |
| `repeat` | 불 | [반복] 켜짐 |
| `cycle` | 정수 | 몇 번째 반복인지 (혼자 하기가 아니면 0) |
| `recording_steps` | 정수 또는 `null` | 가르치기 중 지금까지 쌓인 단계 수 |
| `result_pending` | 불 | [성공]/[실패]를 누를 수 있는지. 혼자 하기의 반복 한 번(바이알 1개)이 끝날 때마다 `true`가 되고, 누르거나 다음 반복이 끝나면 `false` |
| `result_cycle` | 정수 또는 `null` | [성공]/[실패]를 누르면 표시될 반복 번호 |

## 7. 파이 ↔ micro:bit (USB 시리얼)

* 115200bps, 명령 한 줄 = 글자들 + `\n`. 응답도 한 줄.
* 파이는 명령 하나를 보내고 응답을 받은 뒤 다음 명령을 보냅니다. **0.2초 안에 응답이 없으면** 실패 1번으로 세고, 3번 이어지면 `serial_fail`입니다.
* 확장보드가 주기적으로 보내는 상태 정보(`A...$`) 때문에 명령이 깨지는 문제는 기술조사 코드처럼 수신 버퍼를 비우는 방식으로 처리합니다.

| 명령 | 뜻 | 응답 | 상태 |
| --- | --- | --- | --- |
| `P` | 연결 확인 | `OK` | 있음 (기술조사) |
| `M <a1> <a2> <a3> <a4> <a5> <a6> <ms>` | 서보 6개를 한 번에 이동. 각도 0~180 정수, `ms` 0~1000 | `OK` / `ERR <이유>` | **추가 필요.** 1차 시험으로 확인 |
| `S <서보> <각도> <ms>` | 서보 하나 이동 | `OK ...` / `ERR ...` | 있음. **보정 도구에서만 씀** (micro:bit를 노트북 USB에 직접 꽂고 보냄, 시스템 설계 2.4) |
| `C` | WonderCam 결과 읽기 | `OK ...` | 있음, **이번에 안 씀** |
| `D` | 초음파 거리 | `OK <mm>` | 있음, 이번에 안 씀 |

* micro:bit는 범위를 벗어난 각도를 받으면 움직이지 않고 `ERR range`를 보냅니다(관제에서 이미 잘랐어야 하므로 버그 표시).

* 순서는 [엄지, 검지, 중지, 약지, 새끼]. 엄지는 거리 비율, 나머지는 두 마디 각도의 합(°) (시스템 설계 9.2).

### 9.7 `data/tasks/<저장 시각>_<이름>.json` (관제 서비스, 가르치기)

파일 이름 예: `20261125_140311_분주_1회.json`. 이 파일 이름이 `ui/state`의 작업 `id`입니다.

### 9.8 로그 (`data/logs/<실행 시각>/`, 파이 `~/proxyhand/logs/`)

한 줄에 JSON 하나(JSONL). 모든 줄에 `t`(유닉스 시간, 초)와 `type`이 있습니다.

**`events.jsonl` (노트북)**

| `type` | 추가 필드 | SR |
| --- | --- | --- |
| `mode_change` | `car`, `from`, `to`, `cause` (버튼 이름 또는 오류 코드) | SR-39 |
| `cmd` | `car`, `topic`, `fields` (보낸 TCP 명령 그대로) | SR-39 |
| `report` | `car`, `topic`, `fields` (받은 TCP 보고 그대로, `status`는 상태가 바뀔 때만) | SR-39 |
| `task_start` / `task_end` | `car`, `task`, `cycle`, `end_reason` (`done` / `storage_empty` / `stopped`) | SR-39 |
| `bench_change` | `from`, `to` | SR-39 |
| `alert` | `level`, `car`, `code`, `text` | SR-39 |
| `ui_cmd` | `action`과 필드 그대로 | — |
| `result_mark` | `car`, `task`, `cycle` (몇 번째 반복의 결과인지), `result` | SR-40, SR-26 |

**`hand.jsonl` (노트북):** 보낸 `car{n}/hand` 하나마다 `t`, `type`(`"hand"`), `car`, `angles`, `ms`, `src`(`"live"` 또는 `"replay"`). SR-05 갱신 빈도 측정용.

**파이 로그:** `t`, `type` 형식은 같고, `type`은 `state_change`, `cmd`, `error`, `serial` 등을 씁니다.

### 9.9 설정 읽기 규칙 (`shared/config.py`)

* 모든 서비스는 시작할 때 `shared/config.py`로 설정을 읽습니다. 서비스가 직접 YAML·JSON을 열지 않습니다.
* 필수 필드가 빠졌거나, 타입이 틀렸거나, 정거장 ID가 `map.yaml`에 없으면 **오류 메시지를 출력하고 바로 멈춥니다.**
* 보정 파일(`data/calibration/*.json`)이 없으면 관제·맵 비전 서비스는 뜨되, 화면에 "보정 필요"를 띄우고 해당 기능을 막습니다. AiHand 보정값이 없으면 그 작업차의 손 명령, `topcam.json`이 없으면 콕 LED 판단(`cock_led: null`).
